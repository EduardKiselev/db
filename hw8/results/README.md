раздел 7:

- **что такое anti-entropy и зачем нужен nodetool repair - расхождения между репликами исправляются вне пути чтения;**

Anti -entropy — периодическая сверка копий, которая находит расхождения, накопившиеся без чтений; в Cassandra выполняется командой nodetool repair. То есть, если мы не запрашиваем какие то данные, то мы и не будем знать, что различные ноды хранят не консистентное состояние по ним, для поддрежания их констстентности используется nodetool repair

- **когда без repair не обойтись и что происходит при долгой работе без него: реплики расходятся, чтение может вернуть неактуальные данные, tombstones не подчищаются;**

без repair не обойтись если Hinted handoff уже не поможет, то есть нодо отсутвовала больше окна - max _hint_window_in_ms.

Так же важно его проводить регулятно, чаще чем gc_grace_seconds, иначе есть вероятность получить вокрешение tombstone.

Если repair пропущен Tombstone схлопывается по истечении gc_grace_seconds , и реплика с недоставленным удалением может вернуть удалённую строку.

- **чем repair отличается от read repair и hinted handoff: read repair чинит только ключи, затронутые чтением; hinted handoff компенсирует короткие простои узла хинтами.**

Read repair — исправление устаревших копий во время чтения: координатор видит расхождение версий на репликах и чинит отставшую. То есть Read repair затронет только те данные которые при чтении показали расхождение. 

Hinted handoff — механизм доставки: если реплика недоступна, координатор сохраняет недоставленную запись ( hint ) и позже доносит её вернувшемуся узлу. То есть Hinted handoff механизм доставки данных до узла пока узел был недоступен (не продолжтельное время).
